# Alertmanager Dead-Man's Switch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Alertmanager re-sends the always-firing `Watchdog` alert to a healthchecks.io check every 5 minutes, so an outside service emails the user about 20 minutes after the alert pipeline goes silent.

**Architecture:** A `webhook_configs` entry on the existing `Watchdog` receiver in `alertmanager-main`, reading its URL from a SealedSecret that CMO mounts into the Alertmanager pods (`url_file`). Everything is gated by a new `alertmanager.heartbeat.enabled` flag in the `monitoring-config` chart. The Secret ships one commit before the mount, because CMO mounts it without `optional: true`.

**Tech Stack:** OKD 4.21 cluster-monitoring-operator (CMO), Alertmanager 0.29.0, Helm (local v4.3.0; ArgoCD renders with its bundled Helm 3), ArgoCD app `monitoring-config`, Bitnami sealed-secrets (`kubeseal` v0.40.0), healthchecks.io (Hobbyist plan).

**Spec:** `docs/superpowers/specs/2026-09-25-alertmanager-deadman-switch-design.md`

## Global Constraints

- Direct to `master`; no branches, no PRs. Commit messages `<scope>: <imperative summary>`, **no Co-Authored-By trailer, no 🤖 footer.**
- No mutating cluster commands from Claude (`oc apply/delete/patch/...`, and no writes inside pods — auto mode blocks them). ArgoCD applies the repo; anything else is user-run.
- The ping URL is a secret: never printed, pasted into chat, logged, or committed in plain text. Verify Secrets by **key names only**.
- healthchecks.io check: name `okd-alertmanager-watchdog`, **period 5 min, grace 15 min**, email notification.
- Secret: `openshift-monitoring/alertmanager-healthchecks`, key `url`, value `https://hc-ping.com/<uuid>`, created with `--from-literal` (no trailing newline).
- Watchdog route: `group_interval: 1m`, `repeat_interval: 5m`. Webhook: `url_file: /etc/alertmanager/secrets/alertmanager-healthchecks/url`, `send_resolved: false`, `max_alerts: 1`.
- Values: `alertmanager.heartbeat.enabled`, `alertmanager.heartbeat.credentialsSecret: alertmanager-healthchecks`.
- **Order: the SealedSecret is live before any commit that lists it under `alertmanagerMain.secrets`.** A missing listed Secret leaves both Alertmanager pods in `ContainerCreating`.
- Shell is zsh: pass command arguments literally or through functions, never through an unquoted variable (`$R`, `$l`) — zsh does not word-split, and the command silently receives one argument.
- Cluster reads: `KUBECONFIG=~/.kube/config-readonly` for `get`; exec reads (Alertmanager metrics, `amtool config routes test`) use the operator login (`oc whoami` → `sudoom`).

## Review Focus

1. **Secret value with a trailing newline or whitespace** (sealed from a file or `echo`, not `--from-literal`): pings would fail with a malformed URL. Expected: the first ping succeeds. Pinned in Task 2 Step 11 (`…failed_total{integration="webhook"}` must stay 0 after the first increment) and Task 1 Step 3 (seal only with `--from-literal`).
2. **The mount lands before the Secret exists** (commit 2 pushed early, or the SealedSecret fails to decrypt): both Alertmanager pods stuck `ContainerCreating`, all alerting down. Expected: impossible by order. Pinned in Task 2 Step 1 (the Secret must exist before any template change is committed) and Task 2 Step 10 (pods Running after the roll, else revert).
3. **Email routing regresses** while editing the route block: critical alerts stop reaching the inbox. Expected: unchanged routing for everything except Watchdog. Pinned in Task 2 Step 7 (five `amtool config routes test` cases) and Step 11 (email counters unchanged, no new email failures).
4. **Ping cadence wrong** (inherits 12 h, or pings every minute): the check goes DOWN falsely, or burns log entries. Expected: one ping about every 5 minutes. Pinned in Task 2 Step 11 (two consecutive webhook-counter increments 4–6 minutes apart).
5. **healthchecks.io mail lands in spam or the check has no email integration**: the switch fires and nobody sees it. Expected: DOWN and UP emails in the inbox. Pinned in Task 3 (silence test).

- [ ] **Step 3: Add the values**

In `components/cluster-config/monitoring-config/values.yaml`, directly after the `email:` block's last line (`    credentialsSecret: alertmanager-mailjet`), add:

```yaml

  # Dead-man's switch (spec: docs/superpowers/specs/2026-09-25-alertmanager-deadman-switch-design.md).
  # Watchdog is re-sent every 5 minutes to a healthchecks.io check (period 5 min,
  # grace 15 min), which emails from OUTSIDE the cluster when the pings stop --
  # the one failure the email route above cannot report, because Alertmanager
  # runs in the cluster it would be reporting on. The ping URL is sealed in
  # templates/sealed-alertmanager-healthchecks.yaml (key `url`) and read via
  # url_file. The Secret MUST exist before this is enabled: CMO mounts it without
  # optional: true, and a missing one leaves both Alertmanager pods in
  # ContainerCreating. Requires email.enabled (the alertmanager.yaml template is
  # behind it). A healthchecks.io DOWN email means: look at the cluster now.
  heartbeat:
    enabled: true
    credentialsSecret: alertmanager-healthchecks
```

- [ ] **Step 4: Build the secrets list from both flags**

```yaml
      # Alertmanager pods in ContainerCreating. Changing this list rolls them.

{{- if .Values.alertmanager.email.enabled }}
        - {{ .Values.alertmanager.email.credentialsSecret }}
```

- [ ] **Step 5: Route and receiver**

In `templates/alertmanager-config.yaml`, replace:

```yaml
        # Watchdog fires CONTINUOUSLY by design -- it is the heartbeat proving
        # the alert pipeline works. Routing it to email would deliver a message
        # every repeat_interval forever, and an inbox that does that stops being
        # read within a week. It is deliberately sunk into a null receiver.
        - receiver: "Watchdog"

```

with:

```yaml
        # Watchdog fires CONTINUOUSLY by design -- it is the heartbeat proving
        # the alert pipeline works. It never goes to email (a message every
        # repeat_interval forever trains the reader to ignore the inbox). With
        # heartbeat.enabled it is re-sent every 5 minutes to a healthchecks.io
        # check instead, which emails from outside the cluster when the pings
        # stop; otherwise it is sunk into the empty Watchdog receiver.
        # repeat_interval is checked after each group_interval and must be a
        # multiple of it: 1m/5m = one ping about every 5 minutes.
        - receiver: "Watchdog"
          matchers: ["alertname = Watchdog"]
{{- if .Values.alertmanager.heartbeat.enabled }}
          group_interval: 1m
          repeat_interval: 5m
{{- end }}
```

and replace:

```yaml
      - name: "Watchdog"
      - name: "Critical"
```

with:

```yaml
      - name: "Watchdog"
{{- if .Values.alertmanager.heartbeat.enabled }}
        webhook_configs:

          # exclusive, so the ping URL never appears in this rendered config.
```
