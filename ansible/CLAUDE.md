## Non-cluster infrastructure — when to use `ansible/` vs `components/`

- `components/` and `bootstrap/` are for things ArgoCD applies to the OKD cluster. Single source of truth, automated sync, selfHeal, etc.
- `ansible/` is for things that live **outside the cluster** but still need version-controlled, idempotent configuration — e.g. the home DNS servers (`technitium/` — **dns-master `.12` + dns-slave `.13`**, two RPi 3B+ boxes,
  joined in a Technitium **native Cluster** since 2026-08-26) and the NAS (`truenas/`).
- **Why split this way:** DNS (and similar foundational LAN services) must not be circularly dependent on the OKD cluster being up. If the cluster's storage hangs (2026-05-12 incident), the dashboards go dark — losing DNS at the same time would compound the outage.
- Each `ansible/<topic>/` directory is a self-contained Ansible playbook: `inventory.yml`, `playbook.yml`, role dirs, and a `README.md` with the bootstrap walkthrough + day-2 flow. Apply manually from a workstation; do not wire into ArgoCD.
- **All-builtin invariant**: `ansible/` playbooks use `ansible.builtin.*` modules only — no `community.general` / `ansible.posix` / etc. Keeps the operator workstation setup to a single `ansible-core` install.
- Secrets live in `vars/vault.yml` (Ansible Vault encrypted, gitignored). A `vars/vault.yml.example` template is committed alongside.
- **Vault password is interactive each run** (`--ask-vault-pass`). No `--vault-password-file`, no env-var, no on-disk password file — deliberate. Practical consequence for Claude: **I can't run vault-requiring playbooks on the user's behalf** via Bash, because Bash tool calls aren't interactive. **This now applies only to `ansible/technitium/`** (`playbook.yml`, `upgrade.yml` — both declare `vars_files: vars/vault.yml` unconditionally, which also makes them un-`--syntax-check`-able). **`ansible/truenas/` WAS different, but is NOT any more as of 2026-08-31.** Its vault is still loaded OPTIONALLY from a `pre_tasks` `first_found` with `errors='ignore'` — but that only skips a vault that does not EXIST. `vars/vault.yml` was created on 2026-08-31 to hold the two SMB Time Machine passwords, and `include_vars` on an existing encrypted file needs the password, so **`playbook.yml` now requires `--ask-vault-pass` and I can no longer run it** (same position as technitium). `check.yml` is still read-only and vault-free, and `--syntax-check` still works. Historically, and still true of the guard design — only two things need the vault and both are guarded so their absence skips rather than fails: the SMTP alert-email vars (`truenas_smtp_server is defined`) and, since 2026-08-31, the two SMB Time Machine passwords (`truenas_smb_password_{macmini,mba}`). The SMB role converges everything else without a vault — global `aapl_extensions`, groups, dataset ACLs, shares, service — and **reports per account** that no Mac can authenticate, rather than reporting a clean converged run that nothing can log in to. `ansible/truenas/check.yml` is read-only and vault-free. Claude can also run technitium's `base-only.yml` and `--syntax-check` on anything that does not hard-require a vault.
- **Code-only changes — never propose web UI / manual fixes for `ansible/`-managed boxes.** If a change needs to happen on `dns-master` (or any future Ansible-managed host), it goes through the Ansible role + a playbook re-run. Don't suggest "fix it in the Technitium web UI now" as a quick path — even when it's faster — because the next playbook run won't preserve the manual change unless it's also in the role. If the playbook isn't doing what's expected, debug the role; don't bypass it. Same principle as ArgoCD for the cluster: code is the source of truth.
- **`ansible/truenas` traps found 2026-09-11/12 — each caused a real defect.** (1) **A middleware job method must be called with `midclt call --job`**, or it returns a job id with rc 0 and its failure lands where nothing reads it: `pool.update` failed on every run from 09-08 to 09-11 while every play reported `failed=0`. `core.get_methods` marks job methods; `core.get_jobs` is the job log, and it is a better witness than the play recap. (2) **Quote `ON`/`OFF` in YAML** — unquoted, YAML 1.1 makes them booleans, which is exactly what that `pool.update` was rejecting. (3) **A TrueNAS app is a catalog app whenever a train ships it** (`midclt call catalog.get_app_details <app>`), a custom compose app only when none does: garage and syncthing are catalog, node_exporter is custom. Syncthing was first hand-built without checking, and both of its first-run defects came from that. (4) **The roles never prune and the destroy gate refuses a share-referenced dataset**, so removing a dataset is: remove it from code, delete its export (`sharing.nfs.delete`, no code path), `destroy-empty-dataset.sh --destroy`, then converge — ignoring the script's closing "re-create it" advice, which is for its usual destroy-and-recreate job. Details: `ansible/truenas/README.md`.
