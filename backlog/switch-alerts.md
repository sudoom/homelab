# Alert on the 10G switch: SFP thermals and PSU state

Design and assessment for alerting on the home-switch SFP temperature, PSU state and link-downs; not built. The README TODO keeps a short summary of the item and links here.

Two signals are worth one: (a) `mktxp_interface_sfp_temperature{routerboard_name="home-switch"} > 70` — the `S+RJ10` 10GBASE-T copper module on the "Mac mini" port ran **64–73 C over the full 15 d retention window**, i.e. it straddles the commercial-SFP 70 C ceiling and permanently pins the switch fans (`fan-full-speed-temp` is 65, which is also the max value RouterOS accepts, so there is no threshold left to raise); (b) `mktxp_system_psu2_state{routerboard_name="home-switch"} == 0` — currently `0` and has been for the whole window because the second cord is unplugged, so **this switch is single-corded**. Both matter for one reason: a 3m40s link flap on this switch caused the ~5 h cluster-wide `br-ex.forwarding` outage on 2026-08-07, so a thermal event or a PSU loss on it reproduces that outage with no warning. Note the alert must live in **user-workload** monitoring (mktxp metrics are in UWM, not platform), and — unlike the CNPG/job-failure rules — it would be console-only by default: it's warning severity, and the email routes in `components/cluster-config/monitoring-config/templates/alertmanager-config.yaml` are `severity = critical` plus the named `UserNamespace*`/`CNPGWALArchiveFailing*` matchers, so this rule needs an explicit route added alongside them to reach the inbox. Add a third signal (c) `increase(mktxp_link_downs_total{routerboard_name="home-switch",name="Mac mini"}[1h])` — that port logged **266 link-downs in 15 d** (99.93 % uptime, 0 errors, so ~3 s PHY retrains) and the rate tracks temperature (3.24 flaps/2h at >=69 C vs 0.60 below), i.e. the link is plausibly thermally marginal; the Ceph backnet DAC ports logged zero.

**Relocation is NOT a lever** — the module is already on `sfp-sfpplus12` with both neighbours empty, so MikroTik's no-adjacent-ports guidance is satisfied.

**Heatsinks are not the fix either** (measured 2–3.5 C vs the ~5–8 C needed, plus a published null result on this exact switch+module); the real levers are a front-panel 40 mm fan (~15 C measured) or capping the Mac to 1 Gbps — the port's 15 d peak is 241 Mbit/s, i.e. 2.4 % of link rate. Note `sfp-shutdown-temperature` is 95 C, so this is a noise/link-churn issue, not a thermal-risk one, and **"do nothing" is legitimate**. Settle it first with the free test: disable `sfp-sfpplus12` for 30 min and watch `sfp-temperature` + fan RPM — that bounds the payoff of every module-side option.
