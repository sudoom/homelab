# okderators contribution candidates

Assessment of which operators are worth contributing to okderators; nothing here is started. The README TODO keeps a short summary of the item and links here.

**okderators contribution candidates — assessed 2026-09-14 against what this cluster's catalogs actually offer.** Method: every candidate checked live against `okderators`, `community-operators` and `operatorhubio-catalog` packagemanifests, and against public source in the `openshift` org.

**okderators already ships** (34 packages): ODF/rook/ceph-csi/noobaa, LVMS, local-storage, OADP, MetalLB, nmstate, SR-IOV, PTP, ingress-node-firewall, NetObserv, COO, cert-manager, external-secrets, NFD, GitOps, web-terminal, `okd-pipelines-operator`, service mesh 2 and 3, logging/loki, pf-status-relay, descheduler (broken for 4.21 when assessed; fixed upstream since, `catalog-index:4.21` carries v5.3.0-2026-10-12, installed here 2026-10-24).

**Absent from every reachable catalog AND public in `openshift/*` — the real gaps, ranked by gap × size × testability here:** (1) ~~**fix the descheduler 4.21 build**~~ done upstream by 2026-10-12, not by us; (2) **`vertical-pod-autoscaler-operator`** — no community VPA operator exists at all, small (operator plus the VPA images from `openshift/kubernetes-autoscaler`), and its recommender is the honest answer to this cluster's `KubeCPUOvercommit` (requests 32.7 cores vs 31 on two nodes); (3) **`secrets-store-csi-driver-operator`** — small, pairs with the external-secrets operator already in the catalog; (4) **`cluster-resource-override-admission-operator`, `run-once-duration-override-operator`, `secondary-scheduler-operator`** — tiny single-image operators, no community twins, catalog-completeness value more than demand; (5) **`file-integrity-operator`** — only its console plugin is in community-operators, the operator itself is missing; AIDE works on SCOS; (6) **`lightspeed-operator`** — small (operator, service, console plugin), needs a BYO OpenAI-compatible endpoint, homelab-attractive but carries Red Hat product naming; (7) **`compliance-operator`** — missing here, but its `ocp4-*` node profiles target RHCOS, so results on SCOS are partly noise; (8) **`sandboxed-containers-operator`** — needs the `kata-containers` MCO extension in the SCOS payload; verify that exists before proposing.

**Not worth it:** KubeVirt (OKD Virtualization *is* the community HCO by the docs' own attributes — item under *Queued — platform expansion* [now backlog/kubevirt.md]); **OpenShift AI** (upstream Open Data Hub `opendatahub-operator` is in community-operators, Red Hat's RHOAI midstream org `red-hat-data-services` has only two stale public repos so no ODF-shaped port is possible, and this cluster has no GPU to test on); Windows MCO (community build exists); NVIDIA GPU operator (NVIDIA's, certified catalog; the OKD gap is the driver toolkit, not packaging); Quay/Keycloak/Kafka/Tempo/OTel/KEDA/Kepler/medik8s (upstream community operators exist).
