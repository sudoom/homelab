# Repo CI: shellcheck, secret scanning and the validation chain

Assessment and proposal for CI in this repository; not built. The README TODO keeps a short summary of the item and links here.

**Repo CI: shellcheck + secret scanning + the validation chain that already exists (proposed 2026-08-31, after a SonarQube question).** **There is no CI in this repo at all** — no `.github/workflows`, no pre-commit, no linter config; the only scanner named anywhere is a `trivy` mention in a blog draft.

**SonarQube was evaluated and rejected**: of 265 `.yaml`/`.yml` files, **150 are Helm templates** (Go-templated, so not parseable as YAML until rendered — its Kubernetes IaC analyzer would skip them or emit noise on `{{ .Values.foo }}`), it has **no Ansible analyzer** for the 23 Ansible files, and there is zero application code, so its actual competencies (bugs/smells/complexity/coverage/duplication) have nothing to analyze. Self-hosting it also means a 4 GB-heap JVM + another PostgreSQL on a 3-node no-drain cluster that is actively trying to *shed* storage consumers and has already banked 146 W of savings — a bad trade for analysis it structurally cannot perform.

**What to build instead, in value order:** (1) **`shellcheck`** — 3 scripts, two of them destructive one-shots (`bootstrap-pool.sh` runs `pool.create`, `destroy-empty-dataset.sh` runs `zfs destroy`) with hand-rolled gates and nested `ssh`/heredoc quoting; a quoting bug in `destroy-empty-dataset.sh` was caught by eye on 2026-08-31, which is exactly the class shellcheck automates. (2) **`gitleaks`** — public repo, SealedSecrets, a gitignored vault, and `blog/*-draft.md` feeding a public site, with the "no committed secrets" rule enforced today by discipline alone. (3) **Wire up the validation workflow CLAUDE.md already defines** (`helm lint` → `helm template` → `kubeconform` with the CRD schema location) — it is the documented process, run manually; making it a merge gate is the largest coverage win and introduces nothing new to learn. (4) **`ansible-lint`** — worth it for the 23 files, but *second pass*: it will flag every `ansible.builtin.command` wrapping `midclt`, which is deliberate in `ansible/truenas/` (the REST API is removed in TrueNAS 26 and `uri` cannot speak its JSON-RPC replacement), so it needs rule exclusions or it becomes noise people learn to ignore. Roughly 40 lines of Actions YAML, no hosting, no cluster footprint.
